# TrackBuilder

Cities: Skylines のように、**道路と線路を自由な線形で敷設できる 3D エディタ**です。
TypeScript + three.js で、ビルド済みアセットを一切使わず全ての形状を手続き的に生成しています。

```bash
npm install
npm run dev      # http://127.0.0.1:5173/
npm test         # ロジックのテスト (描画なしで組み立てパイプラインごと動かす)
npm run build    # 型チェック + 本番ビルド
```

起動するとサンプルのネットワークが置かれた状態で始まります。切土・盛土、高架、
トンネル、交差点、踏切、分岐器、立体交差が一通り含まれ、車と列車が走り出します。
「マップ」の**ダイヤ型 IC / トランペット IC** ボタンでは、高速道路のインターチェンジを
組み立てた場面に切り替わります。

## 操作

| 操作 | 内容 |
| --- | --- |
| 左クリック | 始点を指定 → もう一度で確定。そのまま続けて連結できる |
| 右クリック / Esc | 敷設を中断 |
| Shift | 直線 + 15° スナップ |
| Ctrl | スナップを無効化 |
| スナップの目印 | 吸い付いた点に輪が出る (水色=交差点・端点、黄=既存線形への取り付き、緑=平行) |
| PageUp / PageDown | 敷設高さを 3 m 刻みで変更 (±60 m)。立体交差・トンネルはこれで作る。**スナップもこの高さで探す** |
| 平行スナップ あり / なし | 既存の線路・道路の隣から引くと、その線形に平行にスナップする (複線はこれで作る) |
| B / C / X / V | 敷設 / シーサス / 撤去 / 確認 モード |
| 確認 (V) でカーソルを重ねる | その**点**の曲線半径・勾配・縦曲線半径・カントと、区間全体の曲率・勾配のグラフが出る |
| 右ドラッグ・ホイール | 視点移動・拡大縮小 |
| F | 乗車 (一人称視点) の出入り。いま見ている辺りの車両に乗る |
| N | 乗っている車両を次に変える (番号順に一巡する) |
| 乗車中のドラッグ | 運転台から見回す。画面をつかんで回す向き (地図の視点操作と同じ感覚) |

始点が既存の**端点**なら接線と勾配を引き継ぐので、繋いだ所で折れません。線路では
**曲率**も引き継ぎ、緩和曲線でなめらかに繋ぎます。
線路の**途中**ならクリック位置の接線と曲率を引き継ぎ、指した側へ分かれる線形を
プレビューから表示します。既存線路の端点を終点にした場合も、確定前から接線を
揃えてなめらかに接続します。
既に 2 本以上が集まっているノードから引く場合は分岐したい場面なので、向きは自由になります。
これは**続けて引いていても、一度やめて指し直しても同じ**です (交差点に取り付いた直後に
別の向きへ引き始めても、直前の向きに縛られません)。
逆に、引いた線形を既存の**端点に繋いだ**ときは、そのままでは角ができてしまうので、
既存側も少し振って両方をなめらかに繋ぎます (下記「取り付きのなめらか化」)。

**交差点の面の中を指したときは、その交差点に繋ぎます。** 面の中で既存の線形を分割しても
交差点の形が保てない (必ず「交差点が近すぎます」になる) ので、T 字路の上を指して十字路に
する、といった操作がそのまま通ります。面の広さは敷設の判定と同じ `junctionReach` で
測るので、指せる所と置ける所がずれません。

## できること

- **自由な線形** — 平面は連結 3 次ベジエ、縦断は独立したエルミート曲線。曲線半径と縦断勾配を
  それぞれ独立に評価でき、種別ごとの規格 (最小半径・最大勾配・最小縦曲線半径) に照らして
  警告を出す。プレビューは常に診断色 (緑→黄→赤) で表示される。最大勾配は実物の基準より
  5 割ほど緩めてある (生活道路 18%、幹線 13.5%、線路 5%)。地形の起伏に対して敷地が狭く、
  実物どおりの勾配では思うように繋げられないため。
- **一人称視点 (乗車モード)** — 走っている列車・自動車の運転台にカメラを移せる。緩和曲線の
  入り方、勾配の変わり目、トンネルの坑口、分岐器の渡りは、上から見ているだけでは分からない。
  乗っている車両が行き止まりで消えたら近くの車両へ乗り移り、1 両も走っていなければその場で
  次を待つ。
- **線路の緩和曲線** — 線路は**原則、緩和曲線 (クロソイド) つき**で敷ける。直線からいきなり
  円曲線に入らず、曲率を弧長に比例して立ち上げる区間を挟む。終端の曲率は次の区間が引き継ぐ
  ので、繋いでいけば曲率はどの繋ぎ目でも連続になる。曲線の途中から分岐した枝も、親の曲率
  から緩和して離れる。道路は今までどおり円弧のまま (最小半径 12〜45 m の道路に十数 m の
  緩和区間を入れても意味がないため)。
- **縦曲線とカント** — 勾配そのものだけでなく、**変わり方の急さ**にも規格 (最小縦曲線半径) が
  ある。規格を外れる形は作られないので敷設は止まらない。曲線には**カント**が付く。曲率から
  導くので緩和曲線でそのまま立ち上がり、分岐器の面と踏切の手前では 0 に戻る。
- **点ごとの確認** — 確認モード (V) で線形にカーソルを重ねると、**その 1 点**の曲線半径
  (左右つき)・勾配・縦曲線半径 (凸凹つき)・カント・構造形式が出る。あわせて区間全体の
  曲率と勾配をグラフで見せるので、緩和曲線で曲率が弧長に比例して立ち上がる様子と、
  縦曲線で勾配がなめらかに変わる様子がそのまま形で分かる。
- **交差点の自動生成** — 隣り合う枝の路端線の交点から各枝のトリム量を決め、断面端点と
  隅丸めで交差点面を作る。横断歩道・停止線・信号機 (または一時停止標識) を自動配置。
  既存の道路を横切るように引くと、その場で分割・統合して交差点になる。
  隅を丸めるのは交差点だけで、**折れ点 (同じ道が曲がっているだけの 2 枝) では
  路端線の交点をそのまま角に使う**。丸めると道路自身の路端が欠けてしまう。
- **平行スナップ** — 既存の線路・道路の隣から引くと、その線形に**平行**にスナップする。
  間隔は舗装 (道床) の縁が触れ合う幅に決まり、平面形だけでなく**高さと勾配も引き継ぐ**ので、
  曲線でも間隔が開かず、橋・トンネルの境界や踏切の位置も揃う。**複線の種別は無く**、
  線路の複線・三線はこれで作る。既に並んでいる線の外側を指せば 3 線目・4 線目を足せる。
  1 本 1 本が独立したセグメントなので、片側だけ分岐させる・片側だけ橋にする・途中で
  本数を変えるといったことが特別扱いなしにできる。スナップが邪魔なときは Ctrl で
  一時解除、または「平行スナップ なし」で切れる。
- **平行に並んだ線形のまとめ** — 並んで敷かれた線形は、**橋・トンネルの区間を揃える**
  (桁も坑門も横に並んで 1 つの構造物に見える)。線路では、複線を渡る踏切は舗装・遮断機・
  停止線が 1 組の踏切としてまとまり、架線柱は並んだ軌道をまとめて受ける**門型**になる。
- **線路の分岐** — ノードに集まる枝から直進側と分岐側を判定し、進路ごとの接続曲線に沿って
  レールと枕木を敷く。4 叉路はダイヤモンドクロッシングになる。急すぎる分岐角は警告。
  分岐角に応じて**規格の最小半径で振り分けられるだけの長さ**を交差点に取り込み、縦断は
  両端の勾配を引き継ぐ曲線にするので、高低差があっても継ぎ目で折れない。
  **道床も軌道と同じ曲線に沿って曲がる** — 両端の断面を弦で結ぶと、曲線のふくらみの分だけ
  道床が外へ張り出し、線路が道床の真ん中から外れて見えてしまう。
- **踏切** — 道路と線路が同一平面で交わると自動的に踏切になる。複線を渡る所は交点が
  線路の本数だけできるが、施設としては**1 か所の踏切**にまとめる。**高さは線路が優先**で、
  舗装の方が線路の面に合わせて上下・傾斜し、縁石の段差も踏切の中では切り下がる。
  勾配のある線路を斜めに横切っても、舗装のどこを取ってもレールが上に出る (列車が走れる)。
  レールの内側にはフランジ溝が入る。遮断機・警報灯・停止線が付き、周期的に動作する。
  踏切がセグメントの端に来ても、ノードを越えて隣のセグメントまで舗装・遮断機・停止線が続く。
- **路側の設備** — 歩道のある道路には電柱を建て、隣り合う柱の間に配電線を張る。
  線路には架線柱と架線が付く。どちらも交差点・踏切・他の線形に重なる位置は避け、
  空いている側を選ぶ。**配電線は途切れない** — 柱を建てられない所 (橋・トンネル・
  線路の架線と支障する所) では手前で地中に引き込み、向こう側で立ち上げる。
- **車線** — 種別ごとの断面から車線を組み立て、交差点では**進行方向別通行区分**
  (左折・直進・右折) を割り当てる。左側通行なので、歩道寄りの車線が左折、中央寄りの
  車線が右折になり、路面には折れ矢印が描かれる。中央分離帯のある自動車専用道では
  対向車線を横切れないので、右折の進路そのものを作らない。
- **走る車と列車** — 車線どうしを繋いだグラフの上を車両が走る。前車追従 (IDM)、赤信号での
  停止、交差点で交わる進路の取り合い、行き止まりでの転回まで見る。止まる位置は路面に
  描いた**停止線**で、横断歩道を塞がない。並べて敷いた複線は左右の線が逆向きに走り
  (左側通行)、分岐器の進路に従って側線へも入る。
- **高速道路のインターチェンジ** — ダイヤモンド型とトランペット型を組み立てる。
  左側通行なので出入口は本線の左側に付き、ランプの勾配が規格に収まる長さまで
  分岐点を自動で遠ざける。トランペット型では側道を本線の下でそのまま反対側へ抜けさせ、
  ランプどうしが 1 か所も平面交差しない形にしている。
- **接続関係** — 道路・線路・電力網は「どこがどこと繋がっているか」を持っている。
  交通シミュレーションや電力網の判定にそのまま使える形で、HUD には系統数が出る。
  表示の「接続の色分け」を入れると、行き来できるまとまりごとに色が変わる。
- **スナップの目印** — どこに吸い付いているかを、吸い付いた点そのもので示す。交差点・端点は
  **その面の広さの輪**、既存線形への取り付きは**分割する位置の横棒**、平行スナップは
  **基準の線形をなぞる線と間隔の渡り線**。引き始めた点の目印は引いている間ずっと残る。
- **敷設の制限** — 規格 (最小半径・最大勾配)、既存の線形との重なり、桁下の建築限界、
  交差点の取り付き長を、**置く前に**判定する。置けないときはプレビューが赤くなり、
  理由が出て、クリックしても置けない。判定は「何 m 離す」という一律の余裕ではなく、
  **交差点が実際に食べる長さが取れるか**で決める。重なりは中心線どうしではなく
  **幅を持った帯どうし**で見るので、中心線が交わらないまま路面だけが重なる配置
  (相手の舗装の中で行き止まる枝、少しずらして並走する高架) も止まる。引いてきた道の
  上をそのまま引き返す・出てきた道の上に戻ってくる線形も、繋ぎ目の向きと重なりから止まる。
- **立体交差** — 高低差から桁下の建築限界 (道路 4.5 m / 線路 5.7 m) を検査し、足りなければ警告。
  上を跨ぐ側は盛土になる高さでも強制的に橋にするので、下をくぐる線形が埋まらない。
  スナップも高さで選ぶので、**頭上の高架に吸い付いて地上の道が引けない**ということがない。
- **トンネルの中の交差点・延伸** — トンネル区間は地形を切らないので、交差点面をそのまま
  置くと山の中に埋まる。外周から覆工を立ち上げて**地中の空洞**にし、枝のトンネルは
  そこへ開く (坑門は建てない)。長いトンネルの継ぎ目も同じで、途中に壁は立たない。
- **橋・トンネル** — 自然地形との高低差から区間ごとに「地表 / 高架 / トンネル」を決め、
  桁・橋脚・橋台・覆工・坑門を生成する。短すぎる区間は前後に吸収するが、**交差点の口に
  かかる分は地表に戻す** (坑門の柱が交差点の中に立たないように)。立体交差の上側は盛土に
  なる高さでも橋にするが、**下がトンネルなら地表のまま**にする (地中のものは埋まらない)。**橋脚は真下を
  通る道路・線路を避けて**径間の中で位置をずらし、避けられなければその 1 基を省く。
  桁の下では、整地を遮断していても地形が桁より上に出ないようにする (トンネル坑口の
  近くなど、地形より低い所を橋にした区間で路面が埋まらない)。
- **地形** — プロシージャル生成の起伏。傾斜と標高による色分け、等高線、傾斜ヒートマップ。
  道路を敷くと切土・盛土で地形が変形し、消せば元に戻る。

## 設計

処理は依存が一方向に流れるよう、次の順で走ります (`src/render/worldBuilder.ts`)。

```
交差点を解く → 交差を調べる → 構造形式を決める → 整地する → メッシュを作る
```

構造形式の判定に使うのは**整地前**の自然地形なので、整地が判定に影響して振動する、
といったことは起きません。

### 線形 (`src/core/`)

平面線形 (`HorizontalCurve`) と縦断線形 (`VerticalProfile`) を分けて持ちます。実際の道路設計と
同じ構成で、「カーブはきついが平坦」「直線だが急勾配」を独立に評価できます。
平面は弧長テーブルを持つので、等間隔サンプリングも曲率の計算も素直に書けます。

平面線形は**連結 3 次ベジエ**です。制御点を `3n+1` 個持ち、隣り合うピースは節点を共有します。
ほとんどの線形はピース 1 つ (ただの 3 次ベジエ) ですが、緩和曲線は 1 本の 3 次ベジエでは
表せないので、この形にしてあります。緩和曲線を別のセグメントに分ける案は採っていません。
交差点のトリム按分・橋やトンネルの区間統合 (`MIN_STRUCTURE_RUN`)・分割位置のクランプは
どれも「セグメントは数十 m ある」前提の定数で、十数 m の緩和曲線片を混ぜると分岐器が
軒並み警告になり、橋が緩和曲線ごとに途切れてしまうためです。

道路の敷設時は「始点の接線に接し、カーソル位置を通る円弧」を解いてプレビューします
(`arcFromTangent`)。掃引角は 120° で頭打ちにしています。単一の 3 次ベジエで円弧を近似する
都合上、それ以上は誤差が目立つためです。

#### 緩和曲線 (`src/core/easement.ts`)

**線路は原則、緩和曲線 (クロソイド) つきで敷けます。** 直線からいきなり円曲線に入ると
繋ぎ目で曲率が 0 から 1/R へ跳ぶので、その手前に曲率を弧長に比例して立ち上げる区間を
挟みます。線形は

```
緩和曲線 (κa → κ) + 円曲線 (κ)
```

の 2 要素です。終端側の緩和曲線は入れません。**次の区間が終端の曲率を引き継いで**自分の
緩和区間を作るので、繋いでいけば曲率はどの繋ぎ目でも連続になります。曲線の途中から
分岐した枝も、親の曲率から緩和して離れます (`Anchor.curvature`)。未知数 2 (終端曲率・
円曲線長) に対して式が 2 本 (指した点を通る) なので、解はちょうど決まります。

- 直線から入る場合は閉じた級数、曲率を引き継ぐ場合は 8 点ガウス積分で解きます。方向変化を
  0.6 rad までに抑えるので、どちらも機械精度で足ります。
- 緩和曲線長は**移程量** `p ≈ Ls²/(24R)` から逆算します。実物のカント逓減の式 (`5.9V²/R`) は
  この縮尺では使えません (100 km/h・R=120 で 492 m になり、区間長 40〜200 m に収まらない)。
- ニュートン法は円曲線だけで解いた形を初期値にします。円曲線長についての偏微分は終端の
  単位接線そのものなので閉形式で、曲率についてだけ中心差分を使います。円曲線が残らない
  短い引きでは、未知数を (終端曲率, 緩和曲線長) に切り替えて解き直します。
- ベジエ近似は各片をその区間の平均曲率の接触円として置くので、半径は僅かに**大きい**側に
  しか外れません。そのうえで規則が使うサンプラ (`extremeCurvature(48)`) そのもので測り、
  規格を割っていれば設計曲率を縮めて引き直します。

道路には入れていません。最小半径が 12〜45 m なので、30 m の区間に十数 m の緩和区間を
入れても意味がないためです。

#### 縦断と縦曲線

縦断は、始点の勾配を引き継ぎつつ終点の高さに合わせます。終点勾配を「平均勾配に対して
線形に変化する」値 (`2*avg - m0`) にすると素直な縦断になりますが、起伏を追って区間を
つなぐと勾配が区間ごとに増幅して平均の 3 倍まで育ちます。そのため終点勾配は平均勾配に
合わせ、規格を超える場合は始点勾配の方を規格内まで戻します (`solveVerticalTangents`)。

**始点勾配を削る条件は、勾配の値域そのものから決めます。** 3 次エルミートの勾配は

```
q(t) = avg + d · (3t - 1)(t - 1),   d = 始点勾配 - avg
```

なので、値域はちょうど `avg + d` (始点) と `avg - d/3` (t = 2/3 の所) の間です。この 2 つが
規格に収まる `d` なら区間のどこも規格を割りません。以前は代わりに `|d| ≤ 規格 - |avg|` という
もっと厳しい条件を使っていて、平均勾配が規格の半分を超えたあたりから繋げるはずの勾配まで
削ってしまい、継ぎ目で勾配が跳んでいました。

それでも本当に繋げない所 (短い区間で平均勾配が規格ぎりぎり) は残ります。そこは敷設後に
`smoothGradeJoint` が**両側で分け合います**。

勾配そのものだけでなく、**変わり方の急さ (縦曲線半径)** にも上限をかけます。短い区間で
勾配を大きく変えると、勾配は連続でも縦断が折れるためです。3 次エルミートの 2 階微分は
弧長について線形なので極値は必ず両端にあり、この縦断の形 (終点勾配 = 平均勾配) では
最大が `4|d|/L` になります。つまり縦曲線半径の下限はそのまま

```
|Δ勾配| ≤ L / (4 · 規格最小縦曲線半径)
```

という 1 つのクランプになり、サンプリングも反復も要りません。規格を外れる形は作られない
ので、敷設は止めません。

規格値は実物どおりにはできません。実物の線路は 3000 m 以上ですが、この縮尺 (区間長
40〜200 m) では 1 区間で勾配を 1% も変えられず、縦断が真っ平らになってしまいます。実質
「1 区間で変えてよい勾配の量」として較正した値を入れています。

#### カント (`src/build/cant.ts`)

曲線では外側のレールを高くします。**曲率から直に導く**ので、緩和曲線では曲率が弧長に比例して
立ち上がるぶん、カントもそのまま比例して立ち上がります (実物のカント逓減と同じ形になり、
別に逓減区間を持つ必要がありません)。規格最小半径で最大カント、緩い曲線では半径に反比例します。

カントは線形そのものには持たせず、踏切の高さ補正が使っているのと同じ口 (`HeightOffset`) に
載せます。帯・路端・交差点の取り付き断面・標示・当たり判定が同じ関数から同じ値を受け取るので、
継ぎ目が開きません。

**交差点の面と踏切には持ち込みません。**

- 分岐器で直進側にカントがあって分岐側に無いと、交差点の面 (道床) がねじれます。実物でも
  分岐器はカントを抜いた所に置きます。面にかかる手前で 0 に戻します。
- 分岐した先で**道床が重なっている間**も 0 のままにします。分岐器を出てすぐは分かれた
  2 本が同じ所を通っていて、左右のレールが離れきるまでは物理的に 1 枚の面です。そこに
  違うカントを付けると、同じ場所に高さの違う面が 2 枚できてしまいます。線路の途中を
  クリックして分けた分岐器は接線から出るので、重なりは交差点の面 (最大 40 m) より
  ずっと先まで続きます (`overlapReach`)。同じ弧長の点どうしの距離を実際に追い、道床の幅
  ぶん離れた所を重なりの終わりとみなします。
- 面が無い継ぎ目でも、両側のカントが食い違うなら 0 に戻します。曲線と直線がほぼ一直線に
  繋がっている所で、帯に段差ができるためです。
- 踏切も同じく手前で 0 に戻したうえで、舗装の目標面の式そのものもカントを見ます。レール
  頭頂面の傾きを線路方向しか見ないと、カントが付いた所で舗装が片方のレールに潜り、
  もう片方から浮きます。

### 交差点 (`src/network/junction.ts`)

各ノードで枝を方位角順に並べ、隣り合う枝の路端線の交点を解いてトリム量を決めます。
直角 4 叉路で同じ幅員なら、トリム量はちょうど道路の半幅になります。断面端点を順に繋ぎ、
隣接する枝の間には路端線の交点を制御点とする 2 次ベジエで隅丸めを入れます。

線路の分岐器・クロッシングでは、軌道が通り抜ける区間の縁を弦ではなく**その接続曲線に
沿って刻みます**。道床が軌道と同じように曲がるので、分岐の外側だけ道床が張り出す、
といったことが起きません (刻んだ結果リングがねじれる極端な配置では弦に戻します)。

交差点面は 1 枚の多角形ではなく、**横断面の点ごとに 1 本ずつリングを作り**、その間を
帯で埋めています (道路なら 歩道 → 縁石 → 車道 の 3 本)。セグメント側の帯とまったく
同じ断面の点を共有するので、勾配が付いていても継ぎ目が開かず、交差点の中でも歩道と
縁石が途切れません。面の色も断面の色をそのまま使うので、交差点だけ舗装や道床の色が
違って見えることもありません。整地も同じリング (いちばん外側) を焼き込むので、
地形と交差点面の形が食い違うこともありません。

#### 取り付きのなめらか化 (`smoothJoint`)

引いたばかりの線形を既存の線形の端に繋ぐと、そこで折れて「角」になります。実際の道路は
取り付く側だけでなく既存側も少し振って繋ぐので、ここでも**両方の端点接線を二等分線へ
寄せて**折れを消します。端点の位置は動かさないので、繋がっている相手の線形やノードの
位置には影響しません。寄せる量は両方の線形が規格 (最小半径・最大勾配) に収まる範囲までで、
収まらなければ段階的に控えめにし、それでも駄目なら元のまま残します。折れが 60° を超える
場合は「角にしたい」意図とみなして触りません。

緩和曲線を含む線形には触りません。端の制御点だけを振ると中の曲率が壊れますし、そもそも
曲率を接続元から引き継いでいるので折れていません。

#### 勾配のなめらか化 (`smoothGradeJoint`)

縦断は別に均します。平面を見送った線形 (緩和曲線つき = 線路のほとんど、折れが 60° を
超える取り付き) でも掛かるので、繋ぎ目の勾配差がそのまま残りません。端の制御点は触らず
端点勾配だけを動かすため、緩和曲線の入った線形でも安全です。

両側から同じ勾配へ寄せますが、寄れる量は区間ごとに違います。**最大勾配も縦曲線の
2 階微分も端点勾配について 1 次**なので「規格に収まる勾配」はひとつながりの区間になり、
今の値と目標の間を二分するだけで届く限界が出ます。片側しか動けなければ、動ける側が
動けるだけ動きます。

3 叉以上のノード (分岐器) は触りません。そこは交差点の面が高さを繋ぎます。

どの枝から勾配を引き継ぐかも、出入りの向きで決めます。`anchorFromNode` は集まっている枝を
方位ごと全部渡し、`computePlacement` が**出ていく向きの真逆を向いている枝**を「続き元」として
選びます。方位角順の先頭を使っていたときは、分岐器で本線の反対側の勾配を拾って繋ぎ目が
折れていました。

### 整地 (`src/terrain/grading.ts`)

2 段階です。

1. 路面などの「地面に接する面」を高さ場に焼き込む (シード)
2. シードから外側へ、許容法面勾配で高さの**上限と下限**を伝播させ、自然地形をその範囲に
   クランプする

伝播はチャンファ距離変換と同じ 2 パス走査で、`O(セル数)` で終わります。シードから遠い所では
上限 = +∞ / 下限 = -∞ になるので自然地形がそのまま残り、道路の近くだけが法面として繋がります。
この方式は次を保証します。

- 路端で地形と路面が必ず一致する (道路が浮かない・埋まらない)
- 途中が途切れない (空洞ができない)
- 道路を消せば地形が完全に元に戻る (`base` は不変で、毎回 `work` を作り直すため)

橋・トンネルの範囲は `block()` で伝播を遮断します。これにより橋台やトンネル坑口で地形が
垂直に切り立ち、その面を構造物のメッシュが覆う、という形になります。

橋の範囲にはもう 1 つ、**桁の下面という「天井」**を掛けます (`carveTriangle`)。谷を渡る
ぶんには地形が残っていて構いませんが、立体交差やトンネル坑口の都合で「地形より低い所も
橋にした」区間では、遮断した地形がそのまま桁に被さって路面が埋まります。地形が桁より
高い所だけを削るので、高い橋の下の地形はそのまま残ります。

整地の目標は**断面に沿わせます**。路端の高さで一様に均すと、道路のように中央が低い断面では
車道が縁石の分だけ地形に埋まります。逆に線路のように中央が高い断面は、道床が地面の上に
載っているのが正しいので法尻の高さで平らに均します。

高さの違う舗装どうしが重なったとき (平坦な幹線に急勾配の枝が取り付く交差点など) は、
**中心線が近い方**が地面の高さを決めます。常に低い方を採ると高い方が宙に浮くためです。
路肩の余裕幅は、全ての舗装を焼き込んだあとに、まだ空いている所だけへ焼きます。

地形で道路が隠れないよう、路面は整地面よりわずかに持ち上げたうえで polygon offset をかけ、
さらに路面の外周に垂れ壁 (スカート) を下ろして継ぎ目の隙間を塞いでいます。垂れ壁の下端は
**整地後の地形まで伸ばします** (上限 8 m)。勾配の違う枝が集まる交差点では、隅の断面が
幾何的に 2〜3 m の垂直な段差になることがあり、固定長では原理的に塞げないためです。

踏切のまわりだけは特別扱いです。舗装の下は道路の高さ、その外側は線路の断面 (道床の法尻)
と、目標が 1 m ほど食い違うためです。舗装の下は道路に譲り、そこから
**舗装の端 → 道床天端 → 法尻** と 2 段階で戻します。片方に寄せると、道路の路端の下が
掘られて浮くか、線路が地形に埋まるかのどちらかになります。

### 構造形式 (`src/network/structure.ts`)

区間ごとに「地表 / 高架 / トンネル」を、**整地前**の自然地形との高低差から決めます。整地は
地表区間にしか効かないので、判定 → 整地 の順に依存が一方向へ流れ、振動しません。短すぎる
区間は前後に吸収しますが、高低差が大きい所 (路端の垂れ壁では下りきれない深さ) は短くても
構造物のまま残します。

これに 2 つの上書きが乗ります。

- **交差点の口にかかる分は地表に戻す。** 坑門の柱や橋台が交差点の中に立たないようにします。
- **立体交差の上側は、盛土になる高さでも橋にする。** そうしないと、下をくぐる線形が上側の
  盛土に埋まります。

2 つめには例外があります。**下がトンネルの中なら、上は地表のまま**にします。地中を通って
いるものは盛土に埋まりようがなく、橋にすると何も跨がない桁が地面の上に残るためです
(道路がトンネルになっている丘の上を線路が越える、といった配置)。見るのは 2 つで、

- 上側が跨ぐ範囲が**すべてトンネル**であること。坑口が交点にかかっていれば、露出している
  所が埋まるので橋のままにします。斜めに交わるほど跨ぐ範囲は長くなるので、交差角も見ます。
- 上側の整地が終わっても**土被りが残る**こと。上側が深い切土だと、掘った先にトンネルが
  顔を出しかねません。

### トンネルの中の交差点 (`src/build/structures.ts`)

トンネル区間では整地を遮断して地山をそのまま残すので、交差点面を置いただけでは山の中に
埋まったままです。そこで交差点面の**外周から覆工を立ち上げ、天井で蓋をした空洞**を作り、
枝のトンネルはそこへ開くようにします。

- 壁を建てないのは**枝の口** (`Junction.openEdge`) だけなので、トンネルの断面がそのまま
  空洞に繋がります
- 天井はトンネル断面のアーチ天端に合わせます。土被りが浅い所では地山を突き抜けないよう
  下げますが、建築限界 (道路 4.5 m / 線路 5.7 m) だけは必ず残します
- 壁の足元は路面より 1 m 下げて、舗装の縁との間に隙間が見えないようにします

坑門は「地山の切り立った面を塞ぐもの」なので、**空洞へ開く端には建てません**。建てると
柱が枝の口に立ち、曲がってきた車がぶつかります。同じ理由で、長いトンネルの途中で
セグメントが分かれた所 (継ぎ目) にも建てません。土被りの下にあるノードで枝が 2 本以上
繋がっていれば、そこはトンネルが続いている所です。

坑口そのものにかかる交差点だけは作れません (敷設規則が止めます)。地形と線形の高さで
決まることなので、掘ってから直せないためです。

### 踏切の高さ合わせ (`src/build/crossing.ts`)

**線路は動かしません。** 列車はレールの上を走るので、レールが舗装に潜っていては困る
一方、線路は道路よりはるかに勾配・線形の自由度が低いからです。代わりに道路の側が

- 中心線の高さ (`deltaY`)
- 道路方向の傾き (`slope`)
- **横断方向の傾き (`roll`)**
- 断面の段差を潰す係数 (`heightScale`)

の 4 つで、レール頭頂面の 6 cm 下を通る平面に合わせます。中心線の高さだけを合わせると、
勾配のある線路が舗装の幅の中で上下するので、路端に近い所でレールが埋まります。段差を
潰さないと、車道より 15 cm 高い歩道の帯にレールが潜って途切れます。補正は舗装が線路に
接している範囲では全量、そこから 14 m かけて 0 に戻します。道路の勾配はその分きつく
なりますが、これは意図した優先順位です。

補正はノードを越えて隣のセグメントにも伝わります (弧長の向きが逆なら傾きの符号も
反転させます)。交差点の断面・整地・路面標示・遮断機も同じ補正を通します。

### 接続関係 (`src/network/connectivity.ts`)

ノードで繋がる線形の組を出し、連結成分に分けます。道路の交差点では集まる枝が
互いに行き来できるものとして全対全で繋ぎ、線路では分岐器の進路 (`Junction.connections`)
だけを繋ぎます。こうすると**ダイヤモンドクロッシングは「交差するが繋がらない」**
という区別がそのまま表現されます。

配電線も同じ考え方で、電柱を節点、径間を辺とするグラフとして持ちます。地中に潜った
区間も辺として繋がっているので、見た目が途切れていても電力網としては 1 つです。

### 確認モードの読み取り (`src/app/inspect.ts`)

確認モード (V) で線形にカーソルを重ねると、`findSegmentNear` が返す**弧長そのもの**で
線形を評価し、その 1 点の値を出します。緩和曲線や縦曲線は「区間の代表値」では分かりません
— 曲率が弧長に沿って変わっていくことそのものが緩和曲線なので、点ごとに見られる必要が
あります。

カントと構造形式は線形からは決まらない (描画側が持っている) ので、`WorldBuilder` を
問い合わせ先として渡します。渡さなくても動き、その 2 つが「不明」になるだけです。

数値の下には、**区間全体の曲率と勾配**を 2 段の帯で描きます。ここで描くのは半径ではなく
**曲率**です。緩和曲線では曲率が弧長に比例するので、曲率で描けば緩和区間がまっすぐな
斜めの線になり、一目で分かります。半径で描くと直線部が無限大に飛んでしまい、同じ形が
双曲線に化けます (人が思い浮かべるのは半径なので、帯の隅にその区間の最小半径を出し、
数値の行にも半径を出しています)。

縦の目盛りは「その区間の最大値」ではなく**規格値と最大値の大きい方**で決めます。規格の
破線が常に同じ高さに出るので、目盛りを読まなくても規格までの余裕が形で分かります。
毎フレーム描き直さないよう、SVG は指している線形が変わったときだけ組み直し、いま見ている
位置の縦線だけを動かします。

曲線半径と勾配の色は**診断色 (勾配・曲率の色分け) と同じランプ**です。配色は
`materials.ts` に 1 か所だけ置き、GLSL へは文字列として埋め込んでいます。カーソルの下の
数値と、そこの舗装の色が必ず一致します。

左右と勾配の符号は**線形の向き (始点 → 終点) 基準**です。画面からは分からないので、
目印から進行方向へ短い棒を出しています。

### 敷設ツールのスナップ (`src/app/buildTool.ts`)

カーソルの行き先は、候補を集めて**いちばん近いもの**に寄せます。候補は 3 つ。

| 候補 | 寄せる先 | 目印 |
| --- | --- | --- |
| ノード | 既存の交差点・端点 | 面の広さの輪 (水色) |
| 既存線形 | その位置で分割して取り付く | 分割位置の横棒 (黄) |
| 平行 | 基準の線形に平行な位置 | 基準をなぞる線と渡り線 (緑) |

中心線までの距離だけで選ぶと、**交差点の面の中を指したときに交差点ではなく枝の途中に
吸い付きます** (面の中では枝の中心線まで 0 m なので必ずそちらが近い)。そこで分割しても
交差点の形は保てないので、面の中を指したときはその交差点のノードに寄せます。面の広さは
敷設の判定と同じ `junctionReach` で測るので、指せる所と置ける所が同じ範囲になります。

種別の違うノードには寄せません (線路のノードに道路を繋ぐと、交差点にも踏切にも
ならないため)。同じ理由で、種別の違う線形は交差 (踏切・立体交差) にしたいので、
途中への取り付きも行いません。

寄せる相手は**高さでも選び**ます。平面で見ると立体交差の上下は重なるので、距離だけで
選ぶと「地上の道を引いているのに頭上の高架に吸い付く」ことになります。基準になるのは
**地形 + 高さ設定** (HUD の「高さ」) で、そこから ±4 m にある線形だけが候補です。
桁下は道路で 4.5 m + 床版 1.1 m あるので、この幅なら上下を取り違えません。高さ設定の
刻み (3 m) より広いので、1 段ずれていても既存の線形には繋がります。トンネルの中の道に
繋ぐときは、高さ設定を土被りのぶんだけ下げます。

例外は**橋**です。カーソルは地形だけでなく**路面**にも当たるので、橋を指していれば
カーソルはその橋の高さを返します。そのときは高さ設定によらず、その橋の高さで働きます
(「橋を指したら、その橋」)。撤去・確認モードも同じ決まりで相手を選びます。

目印 (`src/render/snapView.ts`) は深度テストを切って常に手前に描きます。地形や舗装に
隠れると、いちばん見たい所 (交差点の真ん中・橋の上) で見えなくなるためです。

### 敷設の制限 (`src/network/rules.ts`)

プレビューのたびに `checkPlacement` を通し、1 つでも理由があれば置けません。

| 見るもの | 例 |
| --- | --- |
| 規格 | 曲線半径が最小半径を下回る / 勾配が最大勾配を超える (縦曲線半径は自動で規格内に収めるので、ここでは弾きません) |
| 重なり | 既存の線形と並走する / 浅い角度 (20° 未満) で交差する / 中心線は交わらないのに路面が重なる |
| 折り返し | 引いてきた線形の上をそのまま引き返す / 出てきた線形の上に戻って重なる / 指した所まで届かない |
| 建築限界 | 桁下が道路 4.5 m・線路 5.7 m に足りない (交点だけでなく、路面が重なる範囲すべてで) |
| 交差点の取り付き | 取り付き部が区間に収まらない / 端点が既存の交差点の面の中にある |
| 構造物 | 交差点がトンネルの坑口にかかる (中に作るのは可) |

同じ高さで同じ種別どうしが交差する場合は、その場で分割して交差点になるので許します。
既存の線形の途中に T 字で取り付ける場合も同じで、端点で繋がる相手は「重なり」として
数えません。

重なりは中心線どうしの距離ではなく、**幅を持った帯 (長方形) どうし**で見ます。中心線が
交わらなくても路面は重なるからです — 相手の舗装の中で行き止まる枝、交点を作らずに
すれ違う線形、少しずらして並走する高架。帯として見れば、突き当たり・すれ違い・並走を
同じ式 (分離軸) で扱え、「あと何 m 離せばよいか」もそのまま出ます。桁下の建築限界も、
交点の 1 点ではなく**路面が重なっている範囲すべて**で見ます (交点から離れた所で桁が
下がってくる立体交差を通さないため)。

繋ぎ目の**向き**も見ます。端点から続きを引くとき、カーソルを真後ろに置くと、接線に
接して真後ろの点を通る円弧が存在しません。円弧の解はそこで直線に潰れるので、放って
おくと**引いてきた道の上をそのまま引き返す**線形ができてしまいます (繋ぎ目で 180°
折れた道)。線形が接線に逆らって出ていく場合は置かせません。ヘアピンのように鋭く
曲がる繋ぎ方 (折れ点) は交差点の側で扱えるので、150° までは通します。真後ろに**近い**
所も同じで、円弧が何百 m も回り込んで掃引角の制限に当たり、指した所まで届きません。
届いていない線形は「クリックした所とは違う道」なので、これも止めます。

端点で繋がる相手を重なりから外していると、**出ていった線形の上に戻ってくる**配置も
通ってしまいます。そこで、両端とも同じ 1 本に繋がる線形だけは、繋ぎ目のまわりを除いて
路面の重なりを見ます。除く長さは「規格最小半径で曲がって幅の分だけ横に逃げる弧長
√(2Rw)」と「その交差点の面の広がり」の大きい方。分岐器やランプのように浅い角度で
分かれて**別の所へ抜ける**線形は、離れきるまで何十 m も路盤を共有するのが当たり前
なので、ここでは触りません。

交差点・踏切になる所は、路面が重なって当たり前なので判定から外します。外す範囲は
「交差点が食べる長さ」(`crossingTrim`) と同じ式で決めるので、交差点の外まで広がることは
ありません。線が節で分かれていて、その節の上で交わる場合 (踏切の真上に線路のノードが
ある、など) は、交点が隣のセグメントの側にだけ立ちます。端が節で続いているときは
そこも交差点の中として扱います。

トンネルの**坑口**にかかる交差点だけは、形の問題ではなく**掘ってから直せない**ので
別に見ます。交差点の口に坑門が立って、曲がってきた車がぶつかるからです。判定は、
交差点になる点 (既存ノード・取り付き・同一平面の交差) のまわりで「交差点が食べる長さ +
坑門の余裕」を線形に沿って歩き、そこに**トンネルと地表の境目**があるかどうかで行います。
全部トンネル (= 空洞の中の交差点) でも、全部地表でも構いません。地形を横に見ないのは、
山腹を走っているだけの道路を巻き込まないためです。

道の延伸 (繋いでも 2 枝にしかならない端) は交差点になりません。交差点の面も坑門と
喧嘩する口もできないので、トンネルの中でもそのまま延ばせます。

交差点の判定は、交差点を解くときとまったく同じ計算 (`requiredTrims`) を使います。
分割してできる区間それぞれについて、**必要なトリム量が収まるか** (区間長の 45%・40 m・
両端の合計の上限) を見るので、通った配置は形が保たれ、形が乱れるほど詰まった配置は
止まります。新しいノードを作る場合は、その点が既存の交差点の**面の中**に入っていないか
だけを見ます。面の外なら、多少近くても形は保たれるので止めません。

### 車線 (`src/network/lanes.ts`)

`NetworkClass.lanes` が持っているのは断面の中の位置だけなので、「どの車線がどちら向きに
走るか」「交差点でどの車線からどこへ行けるか」をここで組み立てます。左側通行 (`DRIVE_ON_LEFT`)
が前提です。

進路は、入ってきた向きと出ていく向きの**符号付きの角度**で決めます (XZ 平面では外積が
正なら右折)。偏角 35° 以内は直進、160° を超えると転回として扱いません。

流入車線への割り当ては、左から右へ並べた進路 (左折・直進・右折) を車線数で切り分けます。
車線が足りなければ隣り合う進路をまとめ (2 車線なら「左折・直進」と「右折」)、余れば
直進に厚く配ります。突き当たりの T 字のように直進のない交差点では、左右へ均等に配ります。

**中央分離帯のある種別 (`divided`)** では右折の進路を作りません。左側通行で右折すると
対向車線を横切ることになるからです。自動車専用道の出入りがランプに限られ、ランプが
本線の左側に取り付くのは、この 1 つの規則から出てきます。

### 車線グラフと交通 (`src/sim/`)

車両は線形ではなく**車線**の上を走ります。セグメントの車線 (交差点でトリムした範囲) と、
交差点の中を通る進路 (コネクタ) を頂点、走れる順を辺とする有向グラフを組み立て
(`buildLaneGraph`)、シミュレーションはこのグラフだけを見ます。コネクタの形は、流入車線の
終わりと流出車線の始まりの**位置と向き**から 3 次曲線で結ぶので、繋ぎ目が開きません。

交差点の中で経路が近づく進路の組は「競合」として記録します (同じ車線から分かれるだけの
組は除く)。車はコネクタに入る前に、競合する進路が塞がっていないか、合流先に自分が
収まる空きがあるかを確かめます。**別の進路から合流してくる車は、互いが進路の上にいる
間はお互いの車線に現れない**ので、この確認がないと交差点の出口で重なります。

速度は IDM (Intelligent Driver Model) で決めます。信号・進路の取り合い・行き止まりは
「止まっている前車」とみなすと、追従と同じ式で扱えます。相対速度を見る式なので、前車に
追いついたときに行き過ぎて重なることがありません。信号の現示は描画と同じ関数
(`signalStateAt`) を見るので、「青なのに止まったまま」になりません。

止まる位置は**路面に描いた停止線** (`STOP_LINE_OFFSET`) です。交差点の面の際まで出て
止まると、横断歩道を塞いだ車が並ぶことになります。描画と走行が同じ定数を見るので、
線と車がずれません。停止線を引かない進路 (分岐器・行き止まりの転回) では、交差点の面の
際で止まります。

停止線で止まれるかどうかは、**その速度で止まりきれる距離**で決めます。

- 進路の取り合いは「停止線まで + 止まりきれる距離」のうちに確かめます。交差点の直前で
  気付いても間に合わず、横断歩道の上まで出て止まることになります。
- 進入すると決めた進路は、**もう止まりきれない所まで来たら確定**します。確定した進路は
  次のフレームの最初に押さえるので、あとから来た車に横取りされません (横取りされると、
  止まれない所で「やっぱり止まる」ことになります)。まだ止まれるうちに赤や取り合いに
  気付いたら、決めたことを取り消して停止線で止まります。
- 黄で止まりきれず、進路も空いているときはそのまま渡り切ります (ジレンマゾーン)。赤なら
  精一杯止まり、停止線を越えてしまったら渡り切ります。

行き止まりの転回は、**内側どうしの車線の間隔を直径とする半円**です (制御点は 3 次ベジエで
半円を近似する 2/3)。この半円は車線の端から半径のぶんだけ前に膨らむので、行き止まりでは
その分だけ車線を手前で終えます。そうしないと、転回の弧が舗装から飛び出して草の上を
回ることになります。勾配のある道路では、転回する相手の路面より下がらないようにします。

車体の姿勢は、**上向きを固定した基底**から作ります (`bodyQuaternion`)。「+Z から進行方向
への最短回転」で作ると、ほぼ真後ろ (-Z) を向いたときに回転軸が定まらず、勾配のわずかな
上下成分だけで軸が横に倒れて、車が上下反転して表示されます。

車が走る高さは、**描画に使った路面と同じ**にします。踏切のまわりでは舗装が線路に
合わせて 0.8 m ほど上下し、交差点の面は勾配の違う枝の間で反るので、線形をそのまま
たどると車が路面の下を通ってしまいます (橋の上では、その姿が桁の下から見えます)。
セグメントの車線には踏切の補正を通し、交差点の進路は交差点面より下がらないように
します。

### 乗車モード (`src/app/ride.ts`)

走っている車両を 1 両選び、その運転台に目を置きます。ここはカメラにも DOM にも触らず、
**目の位置と向きを返すだけ**です (カメラへの反映は `Viewport`、キーとマウスの割り当ては
`main.ts`)。ブラウザなしで確かめられます。

目の位置は先頭車の中心から前へ `ahead`、床から上へ `up`。どちらも車両の寸法から出します。

- 前後は**先端より少し手前**に置きます。前を走る車両との車間 (`MIN_GAP` = 2.5 m) より前に
  出ると、詰まったときに相手の車体の中が見えてしまいます。
- 上下は**屋根より下**でなければなりません。上に出ると自分の車体の屋根を見下ろすことに
  なり、視界の下半分が車体色で埋まります (箱の外側の面を上から見る形になるため)。車体の
  比率は描画側 (`BODY_SHAPE` / `roofOf`) から読むので、車体の形を変えても目が屋根から
  出ません。実際、実物の着座位置の割合 (車高の 78%) では車 (車高 1.45 m) の屋根から出ます。
- 上向きは鉛直ではなく**車体基準** (線路と直角) に取ります。カントでは傾けません — 車体の
  描画自体がカントで傾かないので、目だけ傾けると窓の外と合わなくなります。

見回しは車体を基準にした左右 (yaw) と上下 (pitch) で、上下は真上・真下の手前で止めます
(真上を向くと姿勢が定まりません)。

目の位置と向きは、短い時定数 (0.05 s / 0.12 s) で追わせます。車線どうしの継ぎ目や踏切の
舗装の段差で目が跳ねないためです。ただし**大きく飛ぶとき (5 m 以上) は追わずに飛びます** —
乗り換えや車両の湧き直しで、マップを横切って滑っていくことになるためです。

車両は行き止まりに着くと消え、敷き直すと全部湧き直します。そのたびに視点を放り出されると
使いものにならないので、**近くの車両へ乗り移り**、1 両も走っていない間はその場で次を待ちます。

`MapControls` は `update()` のたびに注視点と球面座標からカメラを置き直すので、乗車中は
止めておかないと、外から書き込んだ位置が次のフレームで戻されます。近クリップ面も 1 m の
ままでは目の前の路面が切り取られるので 0.4 m に詰めます。どちらも降りるときに戻します。

### 平行スナップ (`src/network/parallel.ts`)

複線・側道は「1 本の種別」ではなく、**既存の線形に平行な線形をもう 1 本敷いたもの**
として作ります。敷設中はカーソルに近い線形を探し、舗装 (道床) の縁が触れ合う間隔
(`parallelSpacing`) だけ横にずらした位置へスナップします。プレビューの線形は、基準に
した線形の区間を切り出して横にずらしたもの (`parallelAlignment`) なので、

- 曲線でも間隔がどこでも一定になる
- **高さと勾配も基準から引き継ぐ**ので、橋・トンネルの境界や踏切の位置が自然に揃う

という性質がそのまま出ます。カーソルが基準の端まで来たらそこで止まり、続けて引くと
隣のセグメントが基準になります。既存の線形の**区切り (ノード) と同じ位置で区切って**
敷けるので、複線の継ぎ目が食い違いません。

曲線のオフセットは、端点を法線方向にずらし、制御点の長さを曲率に応じて縮めます
(半径 R の弧を曲率中心の側へ d ずらすと半径 R − d になる)。この規模の曲線
(最小半径 45 m 以上、ずらす量 10 m 程度) では、正確なオフセット曲線との差は数 cm です。

スナップ先の候補 (ノード・既存線形の途中・平行の位置) は**カーソルにいちばん近いもの**が
勝ちます。線路の路肩 (2.2 m) の外に出れば平行、線形の上に乗れば取り付き、端点の近くでは
ノード、と素直に切り替わります。既にその隣が埋まっている所には寄せないので、並んでいる
線の外側を指せば 3 線目・4 線目が足せます。

### 平行に並んだ線形の扱い

シーサスクロッシングは `C` または「シーサス」を選び、平行な2本の線路の
設置したい中心を指します。4つの分岐器・2本の渡り線・中央のクロッシングを
まとめてプレビューし、クリック1回で敷設します。側線ではコンパクトに、本線では
最小曲線半径を守れる長さまで自動的に広げます。端点に近く長さが足りない場合は、
施工せず理由を表示します。

「どれとどれが平行に並んでいるか」は、敷設のときの操作を覚えるのではなく**線形の形から
求め直します** (`findParallelGroups`)。間隔がだいたい一定で、向きが揃っていて、高さも
近い組を平行とみなします。分割・撤去・サンプルの読み込みなど、どんな作られ方をした
複線でも同じように扱えるためです。まとまりが決まると、

- **橋・トンネルの区間を揃える** (`unifyParallelRuns`)。並んだ線がそれぞれ地形と比べて
  区間を決めると、同じ谷を渡っていても桁の始まりが数 m ずれます。同じ断面の所は
  いちばん強い形式 (トンネル > 橋 > 地表) に揃えるので、桁も坑門も横に並びます。
- **架線柱を門型にまとめる**。線路 1 本ごとに柱を建てると複線の間に柱が林立します。
  いちばん外の軌道の路肩に柱を建て、その間に梁を渡して軌道ごとに架線を吊ります。
  柱の位置は 1 本のときとまったく同じ (路肩の上) なので、足元の高さの扱いは変わりません。
- **踏切を 1 か所にまとめる**。複線を渡れば交点は線路の本数だけできますが、実物の踏切は
  舗装も遮断機も 1 組です。まとめる判定は道路の弧長ではなく world 座標で行います
  (線路の間に道路のノードが来ると、隣り合う交差が別のセグメントに乗るため)。

一方通行の種別 (線路・ランプ) をサンプルとしてまとめて置くときは、右半分の線を敷いた
あとで向きだけ反転します (`Network.reverseSegment`)。端点も形も変わらず a 側と b 側が
入れ替わるだけなので、2 本並べれば左側通行の複線になり、3 本なら中央が上り方向の三線に
なります (`app/sketch.ts` の `drawParallel`。サンプルの組み立て専用で、手で敷くときは
平行スナップを使います)。

### インターチェンジ (`src/app/interchange.ts`)

本線に沿う `u`・直交する `v` の局所座標で組み立て、最後に中心と方位でワールドへ移します。
左側通行では走行車線が本線の左側なので、`+u` 方向を受け持つランプ 2 本は `-v` 側に付き、
出口は交差点の手前 (`u < 0`)、入口は先 (`u > 0`) になります。

**ダイヤモンド型**では、ランプの取り付く先を側道上の 1 つの交差点 (ランプ端末) に
まとめます。**トランペット型**は側道が本線に突き当たって終わる T 字のインターで、
`-v` 側 (東行き) の 2 本は側道の突き当たりに直接付きますが、`+v` 側 (西行き) の 2 本は
本線の反対側に回らなければなりません。そこで**側道を本線の下でそのまま `+v` 側へ抜けさせ**、
その先から 2 本を出します。こうするとランプどうしは 1 か所も平面交差せず、立体交差は
「本線が側道を跨ぐ」1 か所だけで済みます。回り込む側 (西行きの出口) が 200° 余り旋回する
ループランプで、これがトランペットの朝顔にあたります。

本線のランプ分岐点は「側道側の高さの平均 + 桁下高」に固定します。地形が傾いていても
本線と側道の高低差が桁下高のまま保たれるので、ランプの勾配が規格を超えません。それでも
足りない場合は、勾配が収まる長さまで分岐点を交差点から遠ざけます。

ランプは原則まっすぐ引きます。経由点を増やして曲げると、区間ごとに「前の接線に接する
円弧」を解く都合で接線が振動し、本線への取り付き角が浅くなりすぎて交差点が長くなります。
直線なら取り付き角がそのまま弦の向き (30〜37°) になり、交差点の形が素直に決まります。
ループランプだけは円弧上に経由点を置くので、同じ理由で接線が振動しません。

### 路側の設備 (`src/network/occupancy.ts`)

信号機・架線柱・電柱は「自分の線形の路側」に置きますが、そこは交差する別の線形の
真ん中かもしれません。そこで、道路・線路・交差点面の占有領域を格子索引に入れておき、
置く前に必ず問い合わせます。塞がっていれば、交差点から遠ざかる向きに置き直すか、
反対側の路肩に回すか、それでも駄目なら諦めます。

問い合わせには**高さ**も渡します。立体交差では、桁の上の支柱が真下を通る線形の
「上」に来るのが正常だからです。高さが 2 m 以上離れた線形は無視します。
問い合わせる高さは路面ではなく**実際に足を置く高さ**です。路面の高さで問うと、
隣の盛土の上に乗ってしまう場所を「空いている」と誤って答えます。

橋の上では床版の外に地面がないので高欄の内側に寄せ、寄せる余地のない種別
(歩道のない自動車専用道) では立てません。トンネルの区間にも立てません
(地表に合わせると、トンネルの真上の丘に信号だけが生えます)。

**橋脚**も同じ索引に問い合わせます。橋の下は道路・線路が通っているのが普通なので、
径間を等分するだけでは車道のど真ん中に柱が立ちます。塞がっていれば径間の中で前後に
ずらし、どこにも建てられなければその 1 基を省きます (桁は連続しているので、径間が
1 つ長く見えるだけです)。高い所にある交差点の床版も同じ扱いです。

## 検証

`test/adversarial-*.test.ts` は「敵対的検証」用のテストです。デモ配置では踏まない
組み合わせ — 急勾配の取り付き、斜め踏切、分岐器と踏切の重なり、鋭角の交差点、
高架上の交差点、曲線上の踏切、起伏の激しい地形 — を自前で組み立てて、
**具体的な数値の不変条件**で検査します。

`test/adversarial-matrix.test.ts` は、種別・交差角 (25〜155°)・交差点の間隔 (12〜100 m)・
枝の数 (3〜7)・地形・トンネル・高架・踏切・分岐器を掛け合わせた 120 通りあまりの配置を
総当たりで組み立て、同じ不変条件を一度に掛けます。配置は**敷設ツールと同じ規則**
(`checkPlacement`) を通してから組み立てるので、「作れる配置は必ず正しく描かれ、正しく
走れる」「作れない配置には理由が付く」という形の主張になります。

- 交差点面とセグメントの帯が同じ点を共有しているか (継ぎ目が開かないか)
- 平行に敷いた線の間隔がどこでも一定か、片側だけ分岐・橋にできるか
- 並んだ線の橋が同じ断面で始まり同じ断面で終わるか、架線柱が線路の間に立たないか
- 車線グラフの繋ぎ目が開かず、向きも反転していないか (車が瞬間移動しないか)
- 車が逆走・脱線しないか、同じ車線の車どうしが重ならないか
- 車が路面の下を通っていないか (踏切の上下・交差点面の反りを含む)
- 交差点で止まる位置が停止線か (横断歩道を塞いでいないか)
- 整地した地形が路面・レール・道床より上に来ていないか、桁の上に被さっていないか
- 路面の縁の垂れ壁が地形まで届いているか (下に穴が開かないか)
- 小物が他の線形の車道・軌道・交差点面の上に立っていないか、浮いていないか
- 橋脚が下を通る道路の車道の上に建っていないか
- 電線が柱の飛んだ区間に張られていないか
- 橋・トンネルの構造物が交差点の建築限界に食い込んでいないか
- 交差点の面どうしが重ならないか、リングがねじれていないか
- 車が舗装の上を走っているか (交差点の面・転回の弧を含む)
- 車体の向きが進んだ向きと合っているか、急に向きを変えていないか
- 詰まって動かなくなる配置がないか

判定は可能な限り**実際に生成されたメッシュの頂点**から行い、実装の定数に依存
しないようにしています。検査コード自体が実メッシュとずれていないかを確かめる
自己点検テストも入っています。

敷設ツールの操作も、カーソル位置からクリックまでを実際に通して確かめます
(`test/buildTool.test.ts`)。T 字路の面の中を指すと交差点に繋がること (続けて引いても、
一度やめて指し直しても同じ形になること)、面の外では今までどおり分割して取り付くこと、
目印が吸い付いた点に出ることを見ています。引いてきた道の上への折り返しも同じ流れで
突きます — 終点から 180° 反対を指しても置けないこと (端点を指し直しても同じ)、真後ろに
近い所は届かないので置けないこと、その一方で前へ続けるのと、道から離れて戻る迂回路は
そのまま置けること。

規則そのものも、通す配置と止める配置の両方で確かめます (`test/editing.test.ts`)。
たとえば「相手の舗装の中で行き止まる枝は止まる / 舗装の外なら通る / 中心線まで届けば
交差点になるので通る」「舗装の縁をかすめて跨ぐ高架は桁下が足りなければ止まる」
「平行スナップの間隔はちょうど通り、1 m 詰めると止まる」のように、境界のすぐ両側を
突きます。種別ごとの最大勾配も、通る勾配と通らない勾配の両方で確かめます。

トンネルの上を越す線形も `test/tunnel.test.ts` で見ています。中央が平らな台地を貫く道路の
上に線路を通し、**橋にならない**こと、坑口にかかる所では今までどおり橋になること、
線路を掘り下げて土被りが残らなくなれば橋に戻ることを、同じ台地で切り分けて確かめます。

トンネルの中の交差点は `test/tunnel.test.ts` で見ています。山を貫く道路に枝を足して、
土被りの深い所なら作れること・坑口にかかる所では止まること、そして**実際に描かれた
構造物**から、交差点の真ん中に天井が張られていること (空洞になっていること)、枝の口に
坑門の柱が立たないこと、山の外の坑口には坑門が残ることを測ります。トンネルの中で
行き止まった道を延ばせることも同じ場面で確かめます。

緩和曲線は `test/easement.test.ts` と `test/railEasement.test.ts` で見ています。前者は
ソルバ単体で、級数・ガウス積分が細かく積分した基準値と一致すること、緩和曲線長がこの
縮尺で使える範囲に収まること、**どの向き・どの距離を指しても規格の最小半径を割らない**
こと (半径 50〜400 m × 方位 ±80° × 距離 40〜320 m の総当たり)、指した点に届くこと、
真後ろを指しても暴走しないこと、同じ入力から必ず同じ線形が出ることを確かめます。
後者は敷設ツールと同じ手順で実際に敷き、繋ぎ目で曲率が跳ばないこと・曲率が弧長に沿って
立ち上がること・繋いでいけばどの繋ぎ目でも曲率が連続になること・曲線の途中から分岐
した枝が親の曲率から出ること・道路は今までどおり円弧のままであることを見ています。

連結ベジエそのものは `test/polybezier.test.ts` で、ピースを増やしても弧長・接線・曲率が
1 ピースのときと変わらないこと、**分割しても 1 本のベジエに潰れないこと**、横にずらしても
ピース数と間隔が保たれること、中間の制御点がネットワークに保存されて復元されることを
確かめます。縦曲線は `test/profile.test.ts` で、2 階微分が数値差分と一致すること・弧長に
ついて線形であること・`L / (4|d|)` の関係が成り立つことに加え、敷設ツールを通したときに
短い区間でも規格に収まること、長い区間では無駄に平らにしないことを見ています。

確認モードの読み取りは `test/buildTool.test.ts` と `test/inspect.test.ts` で見ています。
前者は実際にカーソルを重ねて、曲がる向きが符号で分かること (左右を取り違えないこと)、
報告された曲線半径が**前後 3 点を通る円の半径**と一致すること (別の求め方で突き合わせる)、
線路では曲率が 0 から単調に立ち上がるのに対し道路では入口から曲率が付いていること、
描画側を渡せば構造形式とカントも読めること (デモ配置を実際に組み立てて確かめる) を
確かめます。後者は表示の文字列とグラフの折れ線を素の関数として突き、弧長に比例して
変わる値がまっすぐな斜めの線になること・規格内なら必ず帯に収まること・全て 0 でも
NaN を出さないこと (SVG に NaN が混ざるとブラウザは黙って何も描かない) を見ています。

カントは `test/cant.test.ts` で、曲率に応じて付き規格最小半径で頭打ちになること、
**分岐器の面に取り付く断面が水平になる** (道床がねじれない) こと、カントの付いた曲線でも
交差点の面と帯の継ぎ目が開かないこと、踏切の所でカントが抜けていること、そして
カントが残っていても舗装がレール頭頂面と平行になることを確かめます。加えて、線路の途中を
クリックして分けた分岐器で、**道床が重なっているあいだは両方のカントが一致する**ことを
見ています。中心線どうしの距離を実際に測りながら、重なっている点では差が 0、離れた先では
カントが付いていることの両方を確かめるので、検査が空回りしません。

継ぎ目の勾配は `test/gradeJoint.test.ts` で見ています。値域が許すかぎり引き継いだ勾配が
そのまま残ること、繋げない所では規格を使い切るまで寄せて止まること、デモ配置の線路の
継ぎ目がどこも 0.3% 以内に収まっていること、引き継ぎきれないぶんが両側で分け合われる
こと、折れていない継ぎ目には手を出さないこと、そして分岐で**出ていく向きの反対側にある
枝**から勾配を引き継ぐこと (東へ出れば +3%、西へ出れば -3%) を確かめます。

乗車モードは `test/ride.test.ts` で見ています。目が車体の中の、足回りより上・屋根より下・
先端より後ろ (ただし車間より手前) にあること、勾配のある所では線路と直角に立つこと、
見回しが車体基準で効いて上下の限界で止まること、近い車両に乗って番号順に一巡すること、
乗っていた車両が消えたら近くの車両に移り、1 両も走っていなければその場に留まること、
小さな段差は追いかけて行き過ぎず大きな飛びはそのまま置くことを確かめます。最後に、曲線と
勾配のある線路に列車を走らせて 60 秒ぶん乗り、**目がレールの中心から 0.5 m と離れず、
レール面から 2.2 m の高さを保ち、1 フレームで進む距離が車両の速度を上回らない**
(跳ねない) ことを見ています。

高さで選ぶスナップは `test/buildTool.test.ts` で、地表の道路とその上を跨ぐ高架を作り、
真下を指しても高架に吸い付かないこと・高さ設定を合わせれば吸い付くこと・カーソルが
高架の路面に当たっていれば高さ設定によらず吸い付くこと・撤去モードでも同じように
選ばれることを見ています。車体の姿勢は向き 360° × 勾配で総当たりし、屋根が必ず上を向いていること・
進行方向がそのまま写ること・横に傾かないことを確かめます (`test/vehicles.test.ts`)。

## 現状の制限

- 車両は車線の中心をそのまま走ります。車線変更・追い越し・すり抜けはしません。
  交差点では進路 (コネクタ) を 1 本選んで走り切るので、進路上での譲り合いもしません
  (入る前に競合と合流先を確かめるだけです)。
- 信号は 2 位相を機械的に切り替えるだけで、右折の矢印現示や感応制御はありません。
  交差点の枝が 5 本以上あると、同じ位相の中で交わる進路が出ます (競合の判定で
  止まるので重なりはしませんが、待ち時間が長くなります)。
- 列車は 1 本の線路を一方向にだけ走ります (閉塞や行き違いを持っていないため)。複線は
  平行に敷いて作り、左右の線が互いに逆向きになります (`drawParallel` で置いたサンプルの
  複線がそれです。手で敷いた 2 本目は、向きを変えたければ引く向きで決めます)。
  行き止まりでの折り返しはしません (道路の行き止まりでは転回します)。
- 平行スナップの間隔は種別から決まる固定値 (舗装の縁が触れ合う幅) で、選べません。
  並べた線は橋・トンネルの区間だけを揃えるので、桁・橋脚・橋台は本数ぶん並びます
  (1 つの幅の広い橋にはなりません)。整地もそれぞれが独立に行います。
- 平行かどうかは線形の形から判定します。間隔が 0.55〜1.7 倍から外れる・向きが 10° ほど
  ずれる・高さが 1.5 m 以上違う組は「並んでいない」とみなすので、橋・トンネルの区間も
  架線柱もまとまりません。
- 勾配の違う枝が集まる分岐器では、枝ごとに道床の高さが違うので、交差点面はその間を
  傾いて繋ぎます (本線 3.1% と側線 1.8% が 23 m 先で分かれると 0.3 m の差)。
- 緩和曲線は「緩和曲線 + 円曲線」の 2 要素で、終端側の緩和曲線は入れません。曲率は次の
  区間が引き継ぐので繋げば連続になりますが、**1 区間だけを見ると終端に曲率が残ります**。
  そこで引くのをやめると、線形の末端が曲がったまま終わります。
- 分岐器の中の軌道は両端の接線だけを合わせた曲線で、曲率までは合わせていません
  (40 m 以下・1.2 m 刻みなので、折れとしては見えません)。分岐器に必要な取り付き長も
  単一円曲線の式のままで、緩和曲線の移程量は見ていません。
- カントは交差点の面と踏切の手前で 0 に戻します。分岐器の直前まで曲線が続く配置では、
  その区間だけカントが浅くなります (実物でも分岐器はカントを抜いた所に置きます)。
- 縦曲線半径の規格値は実物どおりではありません。実物の線路は 3000 m 以上ですが、この
  縮尺では 1 区間で勾配を 1% も変えられず縦断が真っ平らになるので、「1 区間で変えて
  よい勾配の量」として較正した値を入れています。
- 交差点の中は一様な舗装で、導流線や停止線から先の車線の描き分けはありません。
  進行方向別の矢印は、停止線の手前に描く分だけの取り付き長がある枝にだけ描きます。
- 深い切土は法面で処理します。擁壁つきの掘割は作りません。
- 交差点は高架の上 (床版と橋脚が付きます) にも、トンネルの中 (覆工の空洞になります) にも
  作れます。作れないのは**坑口にかかる**交差点だけで、交差点の口に坑門が立つからです。
  トンネルの中の交差点は空洞の壁と天井だけを作るもので、拡幅・非常駐車帯・立坑といった
  実物の地下構造はありません。
- 電柱は地表区間にだけ建ちます。橋・トンネル、交差点・踏切、他の線形に重なる位置、
  路面より 1.2 m 以上高い所 (切土の法面) は飛ばし、その区間は地中線になります
  (電力網としては繋がったままです)。信号機・標識も同じ理由で立たない枝があります。
- 編集のたびにネットワーク全体とメッシュを作り直します。数百セグメント規模までを想定しています。
  車両も作り直しのたびに湧かせ直します (通れなくなった車線に取り残されるのを防ぐため)。
- Undo / セーブはありません。
- 交差角が極端に浅い交差点 (幅員に対して交差点の長さが 40 m を超える組み合わせ、
  例えば大通り同士の 36° 未満) は幾何的に解けず、交差点面がねじれます。敷設時は
  20° 未満の交差を禁止しているので、通常の操作ではほとんど作れません。ただし敷設の
  判定はノードでの接線で見るので、**曲線の途中に浅い角度で取り付いた**ときだけは
  すり抜けることがあります (その場合も組み立て時に警告が出ます)。
- 踏切に合わせて道路を上下させる分、取り付きの勾配は種別の規格を超えることがあります
  (勾配のきつい道路が平坦な線路を渡る場合で 13% 程度)。線路を優先した結果です。
  すり付けが ±0.8 m を超える踏切 (交差角が浅い・道路の勾配が急) は敷設を禁止しています。
  それでもデータとして存在する場合は補正を頭打ちにするので、路端に近い所でレールが
  舗装に潜ります。
- 交差点の中の路面は、断面の点ごとのリングを張った面です。踏切の横断勾配は交差点の
  断面にも伝えていますが、交差点の**中**が踏切に飲まれるような配置 (交差点の直下に
  線路が来る) は想定していません。
- 乗車モードの視点は、車両の描画と同じく**カントで傾きません** (レールは傾いていても、
  乗っている目は水平のままです)。車体の箱は外向きの面しか描かないので、運転台から横や
  後ろを向くと自分の車体を素通しで見ることになります。運転はできません — 走っている
  車両に乗るだけで、速度や進路は交通シミュレーションが決めます。
