# TrackBuilder

Cities: Skylines のように、**道路と線路を自由な線形で敷設できる 3D エディタ**です。
TypeScript + three.js で、ビルド済みアセットを一切使わず全ての形状を手続き的に生成しています。

```bash
npm install
npm run dev      # http://127.0.0.1:5173/
npm test         # ロジックのテスト (描画なしで組み立てパイプラインごと動かす)
npm run build    # 型チェック + 本番ビルド
```

起動するとサンプルのネットワークが置かれた状態で始まります。切土・盛土、高架、
トンネル、交差点、踏切、分岐器、立体交差が一通り含まれています。

## 操作

| 操作 | 内容 |
| --- | --- |
| 左クリック | 始点を指定 → もう一度で確定。そのまま続けて連結できる |
| 右クリック / Esc | 敷設を中断 |
| Shift | 直線 + 15° スナップ |
| Ctrl | スナップを無効化 |
| PageUp / PageDown | 敷設高さを 3 m 刻みで変更 (立体交差・トンネルはこれで作る) |
| B / X / V | 敷設 / 撤去 / 確認 モード |
| 右ドラッグ・ホイール | 視点移動・拡大縮小 |

始点が既存の**端点**なら接線と勾配を引き継ぐので、繋いだ所で折れません。
既に 2 本以上が集まっているノードから引く場合は分岐したい場面なので、向きは自由になります。
逆に、引いた線形を既存の**端点に繋いだ**ときは、そのままでは角ができてしまうので、
既存側も少し振って両方をなめらかに繋ぎます (下記「取り付きのなめらか化」)。

## できること

- **自由な線形** — 平面は 3 次ベジエ、縦断は独立したエルミート曲線。曲線半径と縦断勾配を
  それぞれ独立に評価でき、種別ごとの規格 (最小半径・最大勾配) に照らして警告を出す。
  プレビューは常に診断色 (緑→黄→赤) で表示される。
- **交差点の自動生成** — 隣り合う枝の路端線の交点から各枝のトリム量を決め、断面端点と
  隅丸めで交差点面を作る。横断歩道・停止線・信号機 (または一時停止標識) を自動配置。
  既存の道路を横切るように引くと、その場で分割・統合して交差点になる。
  隅を丸めるのは交差点だけで、**折れ点 (同じ道が曲がっているだけの 2 枝) では
  路端線の交点をそのまま角に使う**。丸めると道路自身の路端が欠けてしまう。
- **線路の分岐** — ノードに集まる枝から直進側と分岐側を判定し、進路ごとの接続曲線に沿って
  レールと枕木を敷く。4 叉路はダイヤモンドクロッシングになる。急すぎる分岐角は警告。
  分岐角に応じて**規格の最小半径で振り分けられるだけの長さ**を交差点に取り込み、縦断は
  両端の勾配を引き継ぐ曲線にするので、高低差があっても継ぎ目で折れない。
  **道床も軌道と同じ曲線に沿って曲がる** — 両端の断面を弦で結ぶと、曲線のふくらみの分だけ
  道床が外へ張り出し、線路が道床の真ん中から外れて見えてしまう。
- **踏切** — 道路と線路が同一平面で交わると自動的に踏切になる。**高さは線路が優先**で、
  舗装の方が線路の面に合わせて上下・傾斜し、縁石の段差も踏切の中では切り下がる。
  勾配のある線路を斜めに横切っても、舗装のどこを取ってもレールが上に出る (列車が走れる)。
  レールの内側にはフランジ溝が入る。遮断機・警報灯・停止線が付き、周期的に動作する。
  踏切がセグメントの端に来ても、ノードを越えて隣のセグメントまで舗装・遮断機・停止線が続く。
- **路側の設備** — 歩道のある道路には電柱を建て、隣り合う柱の間に配電線を張る。
  線路には架線柱と架線が付く。どちらも交差点・踏切・他の線形に重なる位置は避け、
  空いている側を選ぶ。**配電線は途切れない** — 柱を建てられない所 (橋・トンネル・
  線路の架線と支障する所) では手前で地中に引き込み、向こう側で立ち上げる。
- **接続関係** — 道路・線路・電力網は「どこがどこと繋がっているか」を持っている。
  交通シミュレーションや電力網の判定にそのまま使える形で、HUD には系統数が出る。
  表示の「接続の色分け」を入れると、行き来できるまとまりごとに色が変わる。
- **敷設の制限** — 規格 (最小半径・最大勾配)、既存の線形との重なり、桁下の建築限界、
  交差点の取り付き長を、**置く前に**判定する。置けないときはプレビューが赤くなり、
  理由が出て、クリックしても置けない。判定は「何 m 離す」という一律の余裕ではなく、
  **交差点が実際に食べる長さが取れるか**で決める。
- **立体交差** — 高低差から桁下の建築限界 (道路 4.5 m / 線路 5.7 m) を検査し、足りなければ警告。
  上を跨ぐ側は盛土になる高さでも強制的に橋にするので、下をくぐる線形が埋まらない。
- **橋・トンネル** — 自然地形との高低差から区間ごとに「地表 / 高架 / トンネル」を決め、
  桁・橋脚・橋台・覆工・坑門を生成する。短すぎる区間は前後に吸収する。
- **地形** — プロシージャル生成の起伏。傾斜と標高による色分け、等高線、傾斜ヒートマップ。
  道路を敷くと切土・盛土で地形が変形し、消せば元に戻る。

## 設計

処理は依存が一方向に流れるよう、次の順で走ります (`src/render/worldBuilder.ts`)。

```
交差点を解く → 交差を調べる → 構造形式を決める → 整地する → メッシュを作る
```

構造形式の判定に使うのは**整地前**の自然地形なので、整地が判定に影響して振動する、
といったことは起きません。

### 線形 (`src/core/`)

平面線形 (`HorizontalCurve`) と縦断線形 (`VerticalProfile`) を分けて持ちます。実際の道路設計と
同じ構成で、「カーブはきついが平坦」「直線だが急勾配」を独立に評価できます。
平面は弧長テーブルを持つので、等間隔サンプリングも曲率の計算も素直に書けます。

敷設時は「始点の接線に接し、カーソル位置を通る円弧」を解いてプレビューします
(`arcFromTangent`)。掃引角は 120° で頭打ちにしています。単一の 3 次ベジエで円弧を近似する
都合上、それ以上は誤差が目立つためです。

縦断は、始点の勾配を引き継ぎつつ終点の高さに合わせます。終点勾配を「平均勾配に対して
線形に変化する」値 (`2*avg - m0`) にすると素直な縦断になりますが、起伏を追って区間を
つなぐと勾配が区間ごとに増幅して平均の 3 倍まで育ちます。そのため終点勾配は平均勾配に
合わせ、規格を超える場合は始点勾配の方を規格内まで戻します
(`solveVerticalTangents`)。接続点の勾配がわずかに不連続になりますが、非現実的な急勾配が
できるよりは望ましい、という判断です。

### 交差点 (`src/network/junction.ts`)

各ノードで枝を方位角順に並べ、隣り合う枝の路端線の交点を解いてトリム量を決めます。
直角 4 叉路で同じ幅員なら、トリム量はちょうど道路の半幅になります。断面端点を順に繋ぎ、
隣接する枝の間には路端線の交点を制御点とする 2 次ベジエで隅丸めを入れます。

線路の分岐器・クロッシングでは、軌道が通り抜ける区間の縁を弦ではなく**その接続曲線に
沿って刻みます**。道床が軌道と同じように曲がるので、分岐の外側だけ道床が張り出す、
といったことが起きません (刻んだ結果リングがねじれる極端な配置では弦に戻します)。

交差点面は 1 枚の多角形ではなく、**横断面の点ごとに 1 本ずつリングを作り**、その間を
帯で埋めています (道路なら 歩道 → 縁石 → 車道 の 3 本)。セグメント側の帯とまったく
同じ断面の点を共有するので、勾配が付いていても継ぎ目が開かず、交差点の中でも歩道と
縁石が途切れません。面の色も断面の色をそのまま使うので、交差点だけ舗装や道床の色が
違って見えることもありません。整地も同じリング (いちばん外側) を焼き込むので、
地形と交差点面の形が食い違うこともありません。

#### 取り付きのなめらか化 (`smoothJoint`)

引いたばかりの線形を既存の線形の端に繋ぐと、そこで折れて「角」になります。実際の道路は
取り付く側だけでなく既存側も少し振って繋ぐので、ここでも**両方の端点接線を二等分線へ
寄せて**折れを消します。端点の位置は動かさないので、繋がっている相手の線形やノードの
位置には影響しません。寄せる量は両方の線形が規格 (最小半径・最大勾配) に収まる範囲までで、
収まらなければ段階的に控えめにし、それでも駄目なら元のまま残します。折れが 60° を超える
場合は「角にしたい」意図とみなして触りません。

### 整地 (`src/terrain/grading.ts`)

2 段階です。

1. 路面などの「地面に接する面」を高さ場に焼き込む (シード)
2. シードから外側へ、許容法面勾配で高さの**上限と下限**を伝播させ、自然地形をその範囲に
   クランプする

伝播はチャンファ距離変換と同じ 2 パス走査で、`O(セル数)` で終わります。シードから遠い所では
上限 = +∞ / 下限 = -∞ になるので自然地形がそのまま残り、道路の近くだけが法面として繋がります。
この方式は次を保証します。

- 路端で地形と路面が必ず一致する (道路が浮かない・埋まらない)
- 途中が途切れない (空洞ができない)
- 道路を消せば地形が完全に元に戻る (`base` は不変で、毎回 `work` を作り直すため)

橋・トンネルの範囲は `block()` で伝播を遮断します。これにより橋台やトンネル坑口で地形が
垂直に切り立ち、その面を構造物のメッシュが覆う、という形になります。

整地の目標は**断面に沿わせます**。路端の高さで一様に均すと、道路のように中央が低い断面では
車道が縁石の分だけ地形に埋まります。逆に線路のように中央が高い断面は、道床が地面の上に
載っているのが正しいので法尻の高さで平らに均します。

高さの違う舗装どうしが重なったとき (平坦な幹線に急勾配の枝が取り付く交差点など) は、
**中心線が近い方**が地面の高さを決めます。常に低い方を採ると高い方が宙に浮くためです。
路肩の余裕幅は、全ての舗装を焼き込んだあとに、まだ空いている所だけへ焼きます。

地形で道路が隠れないよう、路面は整地面よりわずかに持ち上げたうえで polygon offset をかけ、
さらに路面の外周に垂れ壁 (スカート) を下ろして継ぎ目の隙間を塞いでいます。垂れ壁の下端は
**整地後の地形まで伸ばします** (上限 8 m)。勾配の違う枝が集まる交差点では、隅の断面が
幾何的に 2〜3 m の垂直な段差になることがあり、固定長では原理的に塞げないためです。

踏切のまわりだけは特別扱いです。舗装の下は道路の高さ、その外側は線路の断面 (道床の法尻)
と、目標が 1 m ほど食い違うためです。舗装の下は道路に譲り、そこから
**舗装の端 → 道床天端 → 法尻** と 2 段階で戻します。片方に寄せると、道路の路端の下が
掘られて浮くか、線路が地形に埋まるかのどちらかになります。

### 踏切の高さ合わせ (`src/build/crossing.ts`)

**線路は動かしません。** 列車はレールの上を走るので、レールが舗装に潜っていては困る
一方、線路は道路よりはるかに勾配・線形の自由度が低いからです。代わりに道路の側が

- 中心線の高さ (`deltaY`)
- 道路方向の傾き (`slope`)
- **横断方向の傾き (`roll`)**
- 断面の段差を潰す係数 (`heightScale`)

の 4 つで、レール頭頂面の 6 cm 下を通る平面に合わせます。中心線の高さだけを合わせると、
勾配のある線路が舗装の幅の中で上下するので、路端に近い所でレールが埋まります。段差を
潰さないと、車道より 15 cm 高い歩道の帯にレールが潜って途切れます。補正は舗装が線路に
接している範囲では全量、そこから 14 m かけて 0 に戻します。道路の勾配はその分きつく
なりますが、これは意図した優先順位です。

補正はノードを越えて隣のセグメントにも伝わります (弧長の向きが逆なら傾きの符号も
反転させます)。交差点の断面・整地・路面標示・遮断機も同じ補正を通します。

### 接続関係 (`src/network/connectivity.ts`)

ノードで繋がる線形の組を出し、連結成分に分けます。道路の交差点では集まる枝が
互いに行き来できるものとして全対全で繋ぎ、線路では分岐器の進路 (`Junction.connections`)
だけを繋ぎます。こうすると**ダイヤモンドクロッシングは「交差するが繋がらない」**
という区別がそのまま表現されます。

配電線も同じ考え方で、電柱を節点、径間を辺とするグラフとして持ちます。地中に潜った
区間も辺として繋がっているので、見た目が途切れていても電力網としては 1 つです。

### 敷設の制限 (`src/network/rules.ts`)

プレビューのたびに `checkPlacement` を通し、1 つでも理由があれば置けません。

| 見るもの | 例 |
| --- | --- |
| 規格 | 曲線半径が最小半径を下回る / 勾配が最大勾配を超える |
| 重なり | 既存の線形と並走する / 浅い角度 (20° 未満) で交差する |
| 建築限界 | 桁下が道路 4.5 m・線路 5.7 m に足りない |
| 交差点の取り付き | 取り付き部が区間に収まらない / 端点が既存の交差点の面の中にある |

同じ高さで同じ種別どうしが交差する場合は、その場で分割して交差点になるので許します。
既存の線形の途中に T 字で取り付ける場合も同じで、端点で繋がる相手は「重なり」として
数えません。

交差点の判定は、交差点を解くときとまったく同じ計算 (`requiredTrims`) を使います。
分割してできる区間それぞれについて、**必要なトリム量が収まるか** (区間長の 45%・40 m・
両端の合計の上限) を見るので、通った配置は形が保たれ、形が乱れるほど詰まった配置は
止まります。新しいノードを作る場合は、その点が既存の交差点の**面の中**に入っていないか
だけを見ます。面の外なら、多少近くても形は保たれるので止めません。

### 路側の設備 (`src/network/occupancy.ts`)

信号機・架線柱・電柱は「自分の線形の路側」に置きますが、そこは交差する別の線形の
真ん中かもしれません。そこで、道路・線路・交差点面の占有領域を格子索引に入れておき、
置く前に必ず問い合わせます。塞がっていれば、交差点から遠ざかる向きに置き直すか、
反対側の路肩に回すか、それでも駄目なら諦めます。

問い合わせには**高さ**も渡します。立体交差では、桁の上の支柱が真下を通る線形の
「上」に来るのが正常だからです。高さが 2 m 以上離れた線形は無視します。
問い合わせる高さは路面ではなく**実際に足を置く高さ**です。路面の高さで問うと、
隣の盛土の上に乗ってしまう場所を「空いている」と誤って答えます。

橋の上では床版の外に地面がないので高欄の内側に寄せ、寄せる余地のない種別
(歩道のない自動車専用道) では立てません。トンネルの区間にも立てません
(地表に合わせると、トンネルの真上の丘に信号だけが生えます)。

## 検証

`test/adversarial-*.test.ts` は「敵対的検証」用のテストです。デモ配置では踏まない
組み合わせ — 急勾配の取り付き、斜め踏切、分岐器と踏切の重なり、鋭角の交差点、
高架上の交差点、曲線上の踏切、起伏の激しい地形 — を自前で組み立てて、
**具体的な数値の不変条件**で検査します。

- 交差点面とセグメントの帯が同じ点を共有しているか (継ぎ目が開かないか)
- 整地した地形が路面・レール・道床より上に来ていないか
- 路面の縁の垂れ壁が地形まで届いているか (下に穴が開かないか)
- 小物が他の線形の車道・軌道・交差点面の上に立っていないか、浮いていないか
- 電線が柱の飛んだ区間に張られていないか

判定は可能な限り**実際に生成されたメッシュの頂点**から行い、実装の定数に依存
しないようにしています。検査コード自体が実メッシュとずれていないかを確かめる
自己点検テストも入っています。

## ディレクトリ

```
src/
  core/       線形・曲線・メッシュ組み立ての基盤
  network/    ノード/セグメントのグラフ、交差点、交差、構造形式、規格チェック、編集操作
  terrain/    高さ場、地形生成、整地、地形メッシュ
  build/      道路・線路・橋・トンネル・踏切・路面標示の形状生成
  render/     マテリアル (シェーダ注入)、小物、全体の組み立て
  app/        ビューポート、敷設ツール、UI、サンプル
test/         線形・交差点・整地・組み立てパイプラインのテスト
```

デバッグ用に `window.trackBuilder` から主要オブジェクトを触れます。
`window.trackBuilder.lookAt(x, z, distance, azimuth)` で任意の地点を見られます。

## 現状の制限

- 車両・列車は走りません。信号機と遮断機は時間で位相が変わるだけの見た目の演出です。
  接続関係は**セグメント単位**まで (`connectivity`) で、車線単位のレーングラフは
  持っていません (`NetworkClass.lanes` は幅員の定義のみ)。
- 交差点内の導流線・車線矢印は描いていません。交差点面は一様な舗装です。
- 深い切土は法面で処理します。擁壁つきの掘割は作りません。
- 電柱は地表区間にだけ建ちます。橋・トンネル、交差点・踏切、他の線形に重なる位置、
  路面より 1.2 m 以上高い所 (切土の法面) は飛ばし、その区間は地中線になります
  (電力網としては繋がったままです)。信号機・標識も同じ理由で立たない枝があります。
- 編集のたびにネットワーク全体とメッシュを作り直します。数百セグメント規模までを想定しています。
- Undo / セーブはありません。
- 交差角が極端に浅い交差点 (幅員に対して交差点の長さが 40 m を超える組み合わせ、
  例えば大通り同士の 36° 未満) は幾何的に解けず、交差点面がねじれます。敷設時は
  20° 未満の交差を禁止しているので、通常の操作ではほとんど作れません。ただし敷設の
  判定はノードでの接線で見るので、**曲線の途中に浅い角度で取り付いた**ときだけは
  すり抜けることがあります (その場合も組み立て時に警告が出ます)。
- 踏切に合わせて道路を上下させる分、取り付きの勾配は種別の規格を超えることがあります
  (勾配のきつい道路が平坦な線路を渡る場合で 13% 程度)。線路を優先した結果です。
  すり付けが ±0.8 m を超える踏切 (交差角が浅い・道路の勾配が急) は敷設を禁止しています。
  それでもデータとして存在する場合は補正を頭打ちにするので、路端に近い所でレールが
  舗装に潜ります。
- 交差点の中の路面は、断面の点ごとのリングを張った面です。踏切の横断勾配は交差点の
  断面にも伝えていますが、交差点の**中**が踏切に飲まれるような配置 (交差点の直下に
  線路が来る) は想定していません。
